## Latency and cost observation

The current production coaching evaluation used gemini-3.5-flash with 2,768 input tokens and 1,204 reported output tokens. Server evaluation latency was 14.38 seconds; the whole HTTP request took 15.893 seconds. This is one observation, not a population median or p95.

## Measurement contract and rollout

New AI feedback requires five integer scores from 1–10; missing/invalid scores produce an explicit failure rather than invented scores. Legacy/unknown provenance and invalid/fallback results are excluded from progress. Comparisons match rubric, prompt, model, format and difficulty. Existing JSON remains preserved. Human judge results carry separate prompt provenance and stay outside AI progress.

Migration 015 couples lifecycle events to database writes. UUID event IDs, owned session IDs and database timestamps are authoritative; the unique owner/session/event key deduplicates retries. Coaching-view RPC checks authentication, ownership and existing feedback. Events have no free-text payload. Loop ID is null until Phase 1; practice_clicked denotes a click, not completion. Human debate lifecycle currently describes the creator's session, not both participants' activation.

Funnel denominator: distinct owned sessions started after migration. Completion numerator: those sessions with debate_completed. Coaching conversion: coaching_generated → coaching_viewed. Time-to-coaching: start to generation timestamps; report cohort dates, counts and median. Do not backfill legacy sessions or claim WCIL before Phase 1.

MEASUREMENT_ROLLOUT supports on, pilot and off; pilot IDs use MEASUREMENT_PILOT_USERS. off pauses new AI coaching/view requests while preserving readable feedback and database-derived lifecycle events. Keep the additive migration during rollback. Existing human judge behavior has its separate path; do not assume the AI flag disables all generation routes.
